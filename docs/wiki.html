Ariadne Technical Reference Manual

An in-depth guide to Ariadne's internal mechanics, micro-allocation primitives, runtime bytecode instrumentation, reactive stream hooks, and distributed observability bridges.

1. Introduction & Motivation

In modern JVM systems, asynchronous programming models—including thread pools, CompletableFuture, Project Reactor, RxJava, and Java 21 Virtual Threads—introduce severe observability challenges. When an execution fails on a worker thread, standard JVM stack traces are severed at the async boundary. Developers are left with blind, truncated exceptions that show where the code crashed, but not who scheduled it or why it was called.

Ariadne solves this problem. It maintains a continuous causal record across threads with sub-microsecond overhead, reconstructing the full asynchronous ancestry only when an error actually occurs.

2. The Asynchronous Blind Spot Problem

When a method executes synchronously on a single JVM thread, the thread's call stack directly records the entire hierarchy of callers. If an exception is thrown, Throwable.fillInStackTrace() captures this call stack directly from the JVM frame pointers.

However, when execution crosses an asynchronous boundary (for example, submitting a Runnable to an ExecutorService or chaining a Mono.publishOn() in Reactor), the caller thread simply places a task descriptor onto a queue and returns immediately.

The Fundamental Dilemma

Traditional debuggers attempt to solve this by creating a new Throwable() on every single operator creation or scheduling call. Because 99.9% of tasks succeed, this generates massive object allocation, triggers heavy Garbage Collection pauses, and incurs a 10x to 100x throughput penalty. Consequently, tools like Reactor's Hooks.onOperatorDebug() are strictly prohibited in production.

3. Core Mechanical Architecture

Ariadne resolves this dilemma by decoupling causal tracking from stack trace synthesis:

  1. Scheduling Time (Happy Path): When a task is queued, Ariadne allocates a tiny immutable 32–40 byte pointer node (Link) in thread-local TLAB memory. Instead of capturing heavy stack traces, it executes a shallow caller check and indexes an interned registry (SiteRegistry). Allocation takes only ~3.9 ns, amortizing async hop overhead to ~148 ns.
  2. Scheduling Time (Happy Path): When a task is queued, Ariadne allocates a tiny immutable 32–40 byte pointer node (Link) in thread-local TLAB memory. Instead of capturing heavy stack traces, it executes a shallow caller check and indexes an interned registry (SiteRegistry). Allocation takes only < 4 ns, amortizing async hop overhead to ~150 ns.
  3. Execution Time: The worker thread attaches the Link to its active context for the duration of the task, ensuring nested asynchronous spawns inherit their parent.
  4. Failure Time (Exception Path): If an exception occurs, Ariadne walks the lightweight linked list backwards, queries the interned call-site registry, synthesizes an AsyncCausalityException, and attaches it via Throwable.addSuppressed().

4. The Lightweight Link Primitive (32–40 Bytes)

The foundational unit of Ariadne is the immutable io.ariadne.core.Link class. Its memory footprint is strictly calculated according to 64-bit JVM object layout specifications: 

public final class Link {
    public final Link parent;          // 4 bytes (Compressed OOPs) or 8 bytes
    public final int siteId;           // 4-byte integer index into SiteRegistry
    public final long threadId;        // 8-byte primitive caller thread identifier
    public final Object attachment;    // 4 bytes (Compressed OOPs) optional context payload (MDC)
    public final int depth;            // 4-byte integer for O(1) depth tracking and capping
}

Under a 64-bit HotSpot JVM with Compressed OOPs enabled (-XX:+UseCompressedOops, default for heaps < 32GB): the object header occupies 12 bytes, references 4 bytes each, primitive int 4 bytes, primitive long 8 bytes. With 4 bytes of 8-byte alignment padding, the total instance footprint is 40 bytes (or 32 bytes without depth). Without Compressed OOPs, it occupies 48 bytes.

Because these nodes escape the method to cross threads, they are allocated in the thread's local TLAB (Thread-Local Allocation Buffer). Ariadne enforces depth capping at maxDepth (default: 32) at spawn time, ensuring repeating tasks (e.g. ScheduledExecutorService) never accumulate unbounded retained heap memory.

5. Lazy Backward Synthesis

When an exception escapes an instrumented task, AriadneReconstructor.enrich(Throwable) activates:

  • Traverses the Link hierarchy up to a configurable maximum depth (default: 32 hops).
  • Resolves each siteId to its class name, method name, file name, and line number from the SiteRegistry.
  • Constructs an AsyncCausalityException containing synthesized StackTraceElement frames mapping directly to originating call sites.
  • Appends contextual payloads (such as MDC diagnostic maps) to the exception message.
  • Attaches the synthesized cause to the original throwable using Throwable.addSuppressed(), preserving the original exception class and stack.

7. Zero-Code Java Agent

The ariadne-agent module is packaged as a standard Java Agent using ByteBuddy: 

java -javaagent:ariadne-agent-0.1.0-alpha.2.jar -jar application.jar

Upon JVM startup, the agent dynamically attaches byte-code advice to:

  • java.util.concurrent.Executor.execute(Runnable)
  • java.util.concurrent.ExecutorService.submit(Callable)
  • java.util.concurrent.ExecutorService.submit(Runnable)
  • java.util.concurrent.ForkJoinPool.execute(ForkJoinTask)
  • java.util.concurrent.CompletableFuture asynchronous supplier and action stages.
  • Java 21 Thread.ofVirtual().start(Runnable).

The agent automatically checks for the presence of Project Reactor, RxJava, and SLF4J on the application classpath and installs the corresponding adapters without requiring configuration.

8. Reactive Framework Adapters

Project Reactor (ariadne-adapter-reactor)

Attaches to Reactor via Schedulers.onScheduleHook() and Hooks.onOperatorError(). When a task is scheduled on Schedulers.boundedElastic() or Schedulers.parallel(), the active Link is automatically captured and restored during subscription and emission.

RxJava 3 (ariadne-adapter-rxjava)

Utilizes RxJavaPlugins.setScheduleHandler() to wrap Runnable instances before they are dispatched to Schedulers.io() or Schedulers.computation().

9. SLF4J MDC Log Propagation

In distributed microservices, correlation identifiers such as traceId, spanId, and userId are placed in the SLF4J MDC (Mapped Diagnostic Context). Because MDC relies on ThreadLocal, switching threads causes all contextual logging data to vanish.

With ariadne-adapter-mdc:

  1. When AriadneContext.spawn() occurs, the adapter captures a snapshot via MDC.getCopyOfContextMap().
  2. When the worker thread executes the task, it binds the snapshot to the worker thread's MDC.
  3. When the task completes, it cleans up and restores the previous thread context, preventing thread-pool cross-contamination.

10. W3C Tracing & OpenTelemetry Planned for v0.2.0

Roadmap Specification: This module is currently under design for milestone v0.2.0. The specification below outlines the targeted architectural integration.

Ariadne plans native integration with the W3C Trace Context specification via W3CTraceContext:

  • Parses and formats traceparent: 00-4bf92f3577b34da6a3ce929d0e0e4736-00f067aa0ba902b7-01.
  • Generates 128-bit trace IDs and 64-bit span IDs.
  • Injects and extracts headers into/from HTTP request headers.

Additionally, AriadneOtelAdapter will provide a reflection bridge to OpenTelemetry's Span.current(), synchronizing distributed spans with internal JVM causality without introducing compile-time dependencies.

11. Java 21 Scoped Values & Loom Planned for v0.2.0

Roadmap Specification: This experimental carrier is designed for Java 21+ Scoped Values (JEP 446 / JEP 464).

In Java 21, millions of lightweight Virtual Threads can be created concurrently. Traditional ThreadLocal variables can create unexpected memory retention if not aggressively pruned.

Ariadne's planned ScopedValueContextCarrier will utilize JDK 21 java.lang.ScopedValue:

  • Values are immutable and bound strictly to lexical execution scopes.
  • Provides runWhere(Link, Runnable) and callWhere(Link, Callable).
  • Implemented dynamically via reflection so enterprise applications compile on standard Java 21 LTS without requiring --enable-preview.

12. Kotlin Coroutines Bridge Planned for v0.2.0

Roadmap Specification: Planned adapter for seamless Kotlin Coroutine context synchronization.

When using Kotlin Coroutines, tasks suspend and resume across different threads and dispatchers. The upcoming AriadneCoroutineBridge.asElement() will dynamically instantiate a kotlinx.coroutines.ThreadContextElement via Java dynamic proxies: 

// In Kotlin coroutine code:
withContext(AriadneCoroutineBridge.asElement() as CoroutineContext) {
    // Causality is strictly maintained across suspend/resume points
    fetchOrder()
}

15. Getting Started & Installation

Option A: Zero-Code Java Agent (Recommended)

Download ariadne-agent-0.1.0-alpha.2.jar from the GitHub Releases page and add the flag to your JVM startup script: 

java -javaagent:/path/to/ariadne-agent-0.1.0-alpha.2.jar -jar your-app.jar

Option B: Programmatic Maven Dependency

<dependency>
    <groupId>io.ariadne</groupId>
    <artifactId>ariadne-core</artifactId>
    <version>0.1.0-alpha.2</version>
</dependency>
