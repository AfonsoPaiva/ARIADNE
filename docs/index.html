Problem & Solution

Standard JVM thread scheduling discards caller frames. Ariadne solves this by recording lightweight pointer chains at dispatch time.

The Problem

Asynchronous Stack Loss in the JVM

When execution transitions across thread boundaries, standard JVM semantics permanently sever caller diagnostics.

  • ✕
    Caller Frame Severance: When a task is submitted to a ThreadPoolExecutor, ForkJoinPool, or reactive scheduler, the worker thread begins execution at runWorker(). The caller call stack is permanently discarded.
  • ✕
    Blind Production Exceptions: Exceptions thrown inside background tasks lack invocation context. It is impossible to determine which controller, event consumer, or user action initiated the failed operation.
  • ✕
    Prohibitive Eager Diagnostics: Workarounds like new Throwable() on every task dispatch or framework assembly tracking impose a 10× to 100× throughput penalty and heavy garbage collection, making them unsafe for production.
The Solution: Ariadne

Lazy Causal Pointer Reconstruction

Ariadne preserves the causal execution graph with single-digit nanosecond allocation and zero happy-path heap retention.

  • ✓
    40-Byte Causal Pointers: At task dispatch, Ariadne captures an immutable reference link pointing to the caller frame. Link allocation consumes exactly 40 bytes in Eden space with Compressed OOPs enabled (HotSpot 64-bit alignment).
  • ✓
    Zero-Cost Happy Path: Successful executions never capture stack traces, format strings, or allocate StackTraceElement arrays (0 bytes retained GC overhead).
  • ✓
    Lazy Stack Synthesis on Failure: Only when an unhandled exception occurs does Ariadne traverse the pointer chain backwards, appending an AsyncCausalityException with full call-site provenance via Throwable.addSuppressed().
  • ✓
    Zero-Code Java Agent: Bytecode instrumentation intercepts thread pools, CompletableFuture, Virtual Threads, and reactive streams transparently at startup without code changes.
Operational Safety

Total Fail-Safe & Kill Switch

Every advice and reconstructor block is bulletproofed with complete exception shielding. A master runtime kill switch (-Dariadne.enabled=false) and package exclusion list ensure risk-free operations.

Security & Privacy

Data Leakage Prevention

MDC diagnostic attachments in exception messages are disabled by default with strict key allowlisting (ariadne.mdc.allowlist) to prevent tokens, credentials, or PII from leaking to log aggregators.

Bounded Memory

Origin-Preserving Window

Memory is strictly bounded to O(maxDepth). When pruning long-lived or recursive chains, Ariadne guarantees that the root ingress origin (e.g., HTTP controller) is permanently preserved alongside immediate failure context.

Architecture

Traditional tools capture complete Throwables on every task, causing 10×–100× throughput degradation. Ariadne records lightweight pointer chains during scheduling and synthesizes stack frames only upon failure.
